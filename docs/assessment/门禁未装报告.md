## 一、装不上：公开常量缺注释（P-113）

- **要守的规则**：GZ-W-127「公开类型与成员都写中文 XML summary」。公开常量是公开成员，评估问题 P-113 指出 `src/HouseholdRelay/Management/ManagementWeb.cs` 第 23、24 行的 `Scheme`、`SessionClaim` 没有 summary，注释覆盖门禁没有拦。
- **为什么现有门禁拦不住**：`check_csharp_summary_coverage` 看的节点是「有可见性的声明」，按它自己的说明，这类节点不含字段，常量在语法树上是字段。
- **为什么补不上**：一条判据只能挑一种节点，所以要另写一条，看「字段」节点，只看修饰符含 `public` 或 `protected` 的，要求必须有「文档注释」。用 `rule test` 实测，带了 summary 的字段也照样报缺注释。单行 `/// <summary>…</summary>` 和三行写法都一样：引擎在字段节点上取不到文档注释。
- **复现样本**（引擎 2.4.0）：

  ```
  public static class A
  {
      public const string Scheme = "x";           // 应报，报了
      private const int Hidden = 1;               // 不看，没报
      protected static readonly int Shared = 2;   // 应报，报了
      /// <summary>有说明。</summary>
      public const int Documented = 3;            // 不应报，却报了
      internal const int Inner = 4;               // 不看，没报
  }
  ```

  配置要点：`"解法": "按语法树看"`、`"看哪种节点": "字段"`、`"只看": [{"找": "修饰符", "含正则": "\\b(public|protected)\\b"}]`、`"必须有": [{"找": "文档注释"}]`。

- **后续**：这是引擎的毛病，转给 MyCoAI 修「字段节点取文档注释」。修好以前，P-113 由整改单人工补注释，人工核对。

## 三、本工程副本与标准正本的差别

3. **命名审计** `check_csharp_naming_audit`：「文件名与类型名一致」一段排除 `.cshtml.cs`。Razor 页面后台代码按 ASP.NET Core 约定是 `Xxx.cshtml.cs` 里放 `XxxModel`，12 个页面全被报，都是框架约定，不是毛病。

## 四、引擎行为，记下备查

- **有存量时编译检查不启动**：同一级已经报出问题时，引擎不启动外部命令，报「未完成」。本工程把存量登记成棘轮基线后，编译检查才真正跑起来（L3 约 14～18 秒）。往后整改单如果让 L3 冒出新问题，编译也会跟着停，要先修门禁问题。
- **`catalog adopt` 对 `task.compile`、`reply.narration` 报「配置有问题」**：这两条不经目录选用，`rule save` 直接写进去就生效，结果不受影响。
