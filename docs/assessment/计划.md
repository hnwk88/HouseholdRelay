## 接用

### 先装哪些门禁、各在哪一级

动手前先当面问负责人同意：装门禁要改原工程的文件，原工程现在自带一套桌面模板的门禁，那三条 XAML、选项模型、行模型检查在这个网页工程里选不到文件，照样报通过（P-093）。

1. **先修标准门禁的三处毛病**（在本工程 `标准/门禁/` 里改，不算这个工程的整改）：
   - SignalR 边界把名叫 `Clients` 的普通属性当成 SignalR，要改成按 `IHubContext` 与 `Hub` 派生类判；
   - 外键命名和实体命名两条认不出 `src/Core/` 这种领域层，路径表达式要加上 `Core` 目录；
   - 注释覆盖漏了公开常量（P-113）。
2. **装法**：
   - 照 `标准/门禁/第一批/安装记录.md`，换掉自带的桌面模板门禁；
   - 扫描后缀加 `.cshtml`、`.js`、`.cjs`、`.css`、`.html`，扫描根加 `docs`；
   - 第一批 31 条在 **L1** 打开，只查改过的文件，平时写代码就拦新问题；
   - **L3** 全量作为每批整改的验收口径。
3. 第一天的 L3 基线应当是：依赖注入说明 41 条，修完 SignalR 误报后为 0，外键命名的实际数待装后看。

### 整改分几批，每批改哪些文件、对到问题清单的哪几条

**第一批：数据与迁移**（先做，后面几批的仓储和服务都建在新表结构上）

- 新出一版表结构（版本 9），升级前先自动备份 `relay.db`（P-017）：
  - 用量、尝试记录、单价对上游补外键（P-001、P-009、P-067）；
  - 上游改为软删除，用量和尝试记录存当时的上游名称快照（P-018）；
  - 主键改为数据库生成的 64 位整数，GUID 要留的话只作属性列（P-001）。这一项改动面最大，见「风险」。
- 迁移丢数据要报出来：v6 丢弃旧单价行、v4 丢弃不合规的代理地址，都改成「另存加报数」（P-039、P-066）；v4 多个候选时留空，交人确认（P-016）；名称占位文字改为空值加提示（P-065）。
- 涉及文件：`src/Infrastructure/Persistence/*Schema.cs`、`RelayDatabase.cs`、`Repositories/Upstream/`、`Repositories/Usage/`。

**第二批：分层归位**

- 把 `RelayServer.Handle` 的编排（令牌复核、准入、记账、切换循环、错误分类）搬进 Application 的转发服务；主程序只剩 HTTP 适配（P-002）。页面和端点只走应用层接口，不碰 `UpstreamResponses`、`UsageService.StorageError`、`UpstreamService.MaxImportBytes`（P-035）。
- 仓储只留存取：候选状态流转、能否激活、删除检查、8 人上限、换家改记单价，搬回领域或应用层，用成对的领域方法推进状态（P-003、P-008、P-055、P-056）。
- 状态和类别改成封闭枚举，映射处去掉 `_ =>` 兜底，取值不认识时拒绝（P-037、P-049、P-051、P-079）。
- 必需依赖改成必填构造参数，加 `ArgumentNullException.ThrowIfNull`，管理宿主也打开 `ValidateOnBuild`（P-036、P-054、P-115）。
- 「模型名合法」收成 Core 里的一个值对象，配置、探测、记账、定价共用（P-005、P-022、P-068）；其余重复的规则同批收口（P-040、P-041、P-043、P-045、P-047、P-048、P-052、P-119）。

**第三批：稳定与排查**

- 检测状态一定落到终态：获取模型和测试用 `try/finally` 写回，页面读服务给的结论，不自己判原始状态（P-006、P-031、P-032、P-073、P-111、P-053）。
- 异常留记录：
  - 两个宿主恢复文件日志（脱敏后记异常类型和阶段）（P-012、P-020、P-085、P-117）；
  - 清理循环接住所有异常、记下后继续（P-013）；
  - 导入逐家记结果（P-011）；
  - 坏的备用配置报出来（P-010）；
  - 错误归因不再一律推给 Claude Code（P-014）；
  - 中转错误响应带请求编号（P-095）。
- 证书：
  - 私有 CA 私钥由 DPAPI 保护着存下来，换地址或续期只重签服务器证书（P-021）；
  - 到期前 30 天开始提示（P-074）；
  - 导入 PFX、重建 CA 前留旧副本，并加确认项（P-024、P-103）。
- `/healthz` 如实报数据库和上游状态（P-075）；检测改成后台任务，有编号、进度和取消（P-076）。

**第四批：网页读屏**

负责人 2026-11-18 提的两条要求，放在这一批最前面做：

- **上游页改成一家一个按钮，操作进菜单**（负责人原话：「现在这一个上游的零碎太多。应该是那种一个上游一个按钮，按右键或者其它方式出菜单的那种。这样就会少切换很多。」）。
  - 「已保存的上游」改成一列按钮，每家一个，按钮名就是「上游名，状态」，比如「甲中转，在用，已通过」。
  - 在按钮上按空格（负责人定，读屏浏览模式下最稳）或回车，弹出这一家的操作菜单；右键、应用键、Shift+F10 也能打开。菜单用 `role="menu"` 和 `menuitem`，上下键移动，回车执行，Esc 关闭并回到按钮。只列这一家此刻能做的项。
  - 菜单第一项（负责人定）：别的上游是「切换到这一家」；当前在用的那一家是「查看用量」，先做成跳到用量页、只看这一家。其后是选模型并测试、重新获取模型、改名、导出、删除。
  - 菜单做完以后，原来平铺在每家底下的「改名」输入框和各个按钮都去掉。改名、测试要填东西的，从菜单进一个只管这一家的小表单；做完焦点回到这一家的按钮，结果念出来。
  - 页面的七块收成三块：上游列表、添加上游（API 供应商、官方账户、导入）、搬家（导出与导入）。自动切换放进列表上方，做成一个开关（P-127、P-004 同批解决）。
- **用量的每个数都带单位**（负责人原话：「用量里面没有单位，我听上去后面不知道是token还是美元」）。
  - 计数读成「输入 12,345 个 token」「缓存读取 800 个 token」，请求次数读成「请求 30 次，成功 29 次」。
  - 金额读成中文币种名加数，比如「已知金额 0.53 美元」；币种代码换成中文名的映射表只写一份，C# 和 js 共用（同 P-038、P-048）。
  - 表格的表头带单位，比如「输入（token）」「金额（美元）」，表格里的每一格只写数。
  - 管理端用量页、个人用量页、费率页同一口径。

### 批与批的先后次序及原因

数据 → 分层 → 稳定 → 读屏 → 收尾。

- 表结构先定，分层时搬出来的领域方法和仓储接口才不用改第二遍；
- 分层先于稳定，因为异常处理和检测终态要写在新的应用服务里；
- 读屏改的是页面，不依赖前面几批，第二批开始后可以并行，但负责人要实机试，放在稳定之后，免得试完又改。

### 每批怎么算做完

- 编译 0 警告 0 错误；`--isolated-mocks` 跑全部测试，评估范围内全部通过；
- 每条问题至少一条新用例，并且改坏能变红；
- L3 全量里这一批对应的门禁命中归零；
- 第一批另要：拿旧版发布程序生成的真实旧库（不是删表删列伪造的，见 P-086）升级到版本 9，数据条数、单价、用量归属逐项对上；
- 第四批另要：负责人用自己常用的读屏实机过一遍使用者页、个人用量页、上游页。

### 不改的问题及原因

- 官方账户分支：不在评估范围，由负责人自己负责。
- P-070 不改：标准已改。负责人定测试和认证结果要带官方原话（原话：「测试认证要代官方的原话」），商量后改的是标准 GZ-S-002 本身，不开工程例外：管理员在受保护的管理入口看的诊断，可以在中文结论之后带对方原话。现在的做法要核对到新条文：
  - 只在管理页（只绑回环、只有管理员能看）的测试、获取模型、认证结果里带；
  - 先写中文的结论和下一步，再写「对方原话：……」，带上对方的错误类型；
  - 原话先脱敏、再截断，截断时说明；
  - 中转回给家人客户端的错误、个人用量页，都不带；当前代理地址这类本机信息不带（P-070 里读出代理地址的那半句要改）。
- 自动切换（P-015）：开关的行为不动。负责人定，它只是个备胎（原话：「那个开关不要做处理。就是一个备胎。已经很完美了」）：你定的在用上游从不会被它换掉，只在那一家不通时替单个请求临时找备用，每次走了哪家用量里都记着。只改一处，默认值从「升级后默认打开」改成默认关（负责人原话：「绝对是关闭」），放在第三批。曾商量过「空闲一小时进待确认」，已放弃。
- 待负责人定的两项，定之前不动：
  - 网页要不要访问键（GZ-W-169）；
  - 整页重载后提示读屏会不会主动念（GZ-W-061，要实机试）。

## 风险

- 主键改 long 是全表迁移，表与表之间、导出文件里、页面的隐藏字段里都存着 GUID。负责人定了要改（原话：「习惯不能因为工程小就忽略标准」），不开例外。分两步降风险：先出一版补外键和软删除；再单独出一版换主键，先盘清全部引用点。旧版导出的文件仍要能导入。
- 搬 `RelayServer.Handle` 会碰到和官方账户分支混在一起的代码，那几段只原样搬，不改逻辑，由负责人复核。
- 官方账户这批测试现在在干净副本上是红的。整改期间用 `--isolated-mocks` 跑，只看评估范围内的结果，避免把它们的红算成整改引入的。
