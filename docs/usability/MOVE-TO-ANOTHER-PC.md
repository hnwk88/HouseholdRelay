# 把正式中转搬到另一台电脑

适用情形：域名 `www.zkmryl.com` 不变，路由器和公网出口不变，只是服务主机从现在这台电脑换成局域网里的另一台电脑，局域网地址随之改变。外部端口与本机监听端口仍是 8787。

先说结论：这次换机**不能把旧数据目录拷过去接着用**。上游密钥、服务器证书私钥由 Windows 数据保护按「这台电脑上的这个 Windows 用户」加密，换了电脑解不开（`PRIVATE-DEPLOYMENT.md`「备份、升级与回退」最后一段）。所以新电脑是一套全新的实例：上游（连同密钥和官方账户）在旧电脑导出成一个加密文件、到新电脑导入；管理密码、证书、客户端信任、个人令牌都重新来。旧电脑的数据留着当备份，不删。

下面每一步都写了在哪台电脑上做。「旧电脑」指现在跑着中转的工作机，「新电脑」指要搬去的那台。

## 一、搬之前先导出上游、记下其余设置（旧电脑）

1. 打开旧电脑的管理页 `http://127.0.0.1:8788`，登录后先记下导出文件里没有的东西：
   - 上游页：在用的是哪一家、自动切换开关是开还是关。
   - 项目设置：代理方式（不使用代理、自动检测系统代理、手动指定）和手动代理地址。
   - 使用者与令牌：每个使用者的显示名。令牌本身拿不回来，新电脑上会重新发。
   - 用量费率：如果填过估算费率，记下每个模型的价格。
2. **导出上游。** 这一步放在新电脑已经准备好（第二到四节做完）、马上要切路由器之前做，原因见下面的提醒。上游页找到「搬到另一套中转：导出与导入」：
   - 「要导出的上游」默认全部勾上，不用动。
   - 「导出密码」输入一个 12 到 128 个字符的密码，「再输入一次导出密码」再输一遍。这个密码不保存，新电脑导入时要输同一个，忘了就解不开。
   - 按「导出加密文件」。页面读出「已导出几家上游」，浏览器自动下载 `household-relay-upstreams-日期-时间.hrupstreams`；没有自动下载时按页面上的「下载导出文件」。把这个文件拷到新电脑（U 盘或共享文件夹都行），它是加密的。
   - **提醒：官方账户导出就是搬走。** 页面会读出「官方账户……已经搬走」：从这一刻起旧电脑不再用它转发、不再续期，免得两台电脑抢同一份登录。自动切换开着时，旧电脑上的请求会换到其他上游；关着时旧电脑会没有可用上游。所以导出以后尽快在新电脑导入、切路由器。
   - 导出文件里的 API 密钥可以长期留作备份；官方账户那一份只在搬家这一刻有用，新电脑续期一次以后它就作废。
3. 记下旧电脑现在的局域网地址（现在是 `192.168.10.7`），后面改路由器时要用。
4. **退路：没有导出文件时**（旧电脑已经起不来，或者导出文件丢了），改为逐页记下每家上游的供应商名称、地址、所用模型、排列顺序，密钥从你自己保存密钥的地方准备好，到第五节按退路重填。

## 二、准备新电脑（新电脑）

1. **固定局域网地址。** 二选一：在路由器的 DHCP 设置里给新电脑做地址保留（推荐，路由器认网卡地址，每次分到同一个地址）；或者在新电脑网卡上手工设静态地址。下文把这个地址写作 `新地址`，例如 `192.168.10.20`。地址会变的话，路由器映射隔几天就会指错电脑。
2. **固定一个 Windows 用户来跑中转。** 以后启动、升级都用这个用户。换用户同样解不开加密数据。
3. **代理与旧电脑保持一致。** 官方账户和上游都从代理出网。旧电脑开着 `127.0.0.1:7897` 的代理软件；新电脑装同一个代理软件、用同一个节点，出口才不变。只是路由器不变还不够：上游请求走的是代理的出口，不是路由器的出口。
4. **安装 Claude Code。** 官方账户的导入、登录和到期续期都靠本机的 Claude Code 完成，新电脑上必须装好，并能在命令行里运行 `claude --version`。不需要在新电脑上用 Claude Code 登录任何账户。
5. **准备两个目录**，与旧电脑同样的布局：程序目录 `E:\RelayApp`，数据目录 `E:\RelayData`。盘符不同就换成你的盘符，下文同样替换。

## 三、生成程序包并拷到新电脑

在装了开发环境的电脑上，于工程根目录运行（自带运行时，新电脑不用另装 .NET）：

```powershell
dotnet publish src/HouseholdRelay/HouseholdRelay.csproj -c Release -r win-x64 --self-contained -o E:\RelayPublish
```

把 `E:\RelayPublish` 里的全部文件拷到新电脑的 `E:\RelayApp`。再把旧电脑的启动脚本 `E:\RelayData\start-relay.ps1` 拷到新电脑的 `E:\RelayData`；如果程序目录不是 `E:\RelayApp`，用记事本改脚本里 `& 'E:\RelayApp\HouseholdRelay.exe'` 这一处。这个脚本要保留 UTF-8 编码，别用别的工具另存。

## 四、新电脑初始化（新电脑）

1. 在新电脑上打开 PowerShell，签发连接证书。域名和端口与旧电脑完全一样：

```powershell
E:\RelayApp\HouseholdRelay.exe init --host www.zkmryl.com --public-port 8787 --listen-port 8787 --home E:\RelayData
```

2. 开放防火墙的 8787 端口。用管理员身份打开 PowerShell 运行：

```powershell
New-NetFirewallRule -DisplayName 'HouseholdRelay-HTTPS-8787' -Direction Inbound -Protocol TCP -LocalPort 8787 -Action Allow -Profile Any
```

管理页端口 8788 只听本机，**不要**为它开防火墙，也不要在路由器上映射它。

3. 启动服务：

```powershell
Start-Process powershell -WindowStyle Minimized -ArgumentList '-NoExit','-ExecutionPolicy','Bypass','-File','E:\RelayData\start-relay.ps1'
```

4. 在新电脑上打开 `http://127.0.0.1:8788`，输入启动窗口里显示的首次设置引导码（也写在 `E:\RelayData\console.log` 里），设置管理密码。看到引导码说明这是一套新实例，属于正常情况。
5. 按 Ctrl+C 停掉启动窗口里的服务，再用第 3 步的命令重新启动一次，让 HTTPS 监听按新证书启动。HTTPS 页面应读出「监听已启动」和证书名称 `www.zkmryl.com`。

## 五、导入上游（新电脑）

1. 项目设置：代理方式照第一节记下的填。项目设置页会读出「自动检测到 http://127.0.0.1:7897」这类结果，读出的地址要和旧电脑一样。先设代理再导入：官方账户导入时就要经代理连官方。
2. 上游页「搬到另一套中转：导出与导入」里的「导入上游」：「导出文件」选从旧电脑拷来的那个文件，「导出时设的密码」输入导出时设的密码，按「导入上游」。
   - 页面读出「已导入几家上游」，它们按旧电脑上的顺序排在已保存上游的后面，都是尚未测试。
   - 密码输错会读出「导出密码不对」；文件没拷完整或被改过会读出「导出文件被改过或不完整」，回旧电脑重新导出一份。这两种情况一家都不会导入。
   - 某一家没导入（例如新电脑还没装 Claude Code，官方账户导入不了）时，页面读出是哪一家、为什么；其余照常导入。按原因处理后，在新电脑上单独补那一家。
3. 逐家按「选择模型并测试」，测试通过后，切换到第一节记下的在用那一家；自动切换开关照旧设置。
4. 官方账户导入以后由新电脑的 Claude Code 续期。测试时如果回 401，说明这份登录已经失效，在新电脑上按「登录官方账户」重新登录。旧电脑上那个官方账户读作「已导出搬走」，不用再管它。
5. 用量费率：照第一节记下的重新填写。
6. **退路：没有导出文件时**，按第一节第 4 步记下的顺序逐家添加，填名称、地址、密钥，测试通过后激活；官方账户按「导入登录文件」，或按「登录官方账户」重新登录。注意**一份登录只能一处用**：导入以后，原来那份登录在别处（包括旧电脑）都不再用，否则双方续期时会互相挤掉。

## 六、切换路由器映射（路由器）

1. 先停掉旧电脑上的中转：在旧电脑的启动窗口按 Ctrl+C，确认窗口里的服务已退出。不停的话两台电脑同时对外，客户端打到哪台说不准。
2. 进路由器管理页，找到端口映射（也叫虚拟服务器、端口转发），把外部端口 8787 那一条的内网地址从 `192.168.10.7` 改成 `新地址`，内网端口仍是 8787，协议 TCP。
3. 域名解析不用动：域名指向的是路由器的公网地址，公网地址没有变。

**局域网里的电脑怎么到达域名**：局域网内的电脑访问 `www.zkmryl.com`，有的路由器会把它绕回内网（叫 NAT 回流），有的不会。如果某台电脑为此在 `C:\Windows\System32\drivers\etc\hosts` 里手工写过 `192.168.10.7 www.zkmryl.com`，这一行要改成新地址，否则它还会去找旧电脑。现在这台旧电脑本身的 hosts 里没有这一行。

## 七、每台客户端重新装信任、换令牌（每台用中转的电脑）

新实例签发了新的根证书，旧的信任不认它，每台客户端都要重装一次：

1. 在新电脑的管理页「连接说明」下载新的 `HouseholdRelay-client-trust.zip`，记下页面上新的 CA SHA-256 指纹。
2. 在每台客户端按 `PRIVATE-DEPLOYMENT.md`「每台 Windows 电脑的一次性信任」重新安装，运行时带上新指纹。
3. 在新电脑的「使用者与令牌」为每个人创建身份，把新令牌交给本人，客户端里的 `ANTHROPIC_AUTH_TOKEN` 换成新令牌。旧令牌在新实例上本来就不存在，自然失效。`ANTHROPIC_BASE_URL` 仍是 `https://www.zkmryl.com:8787`，不用改。

## 八、搬完后的检查

1. 在一台客户端的浏览器打开 `https://www.zkmryl.com:8787/healthz`，不应有证书警告。
2. 在这台客户端新开终端，用 Claude Code 发一条最小的对话。
3. 新电脑管理页「用量」里应能读到刚才那一条，读得出是哪家上游。
4. 在手机流量下（不连家里 Wi-Fi）也打开一次 `/healthz`，确认从外网能到。

## 九、旧电脑的收尾（旧电脑）

1. 旧电脑上的中转不再启动。它的 `E:\RelayData` 与 `E:\RelayApp` 先留着当备份，确认新电脑稳定用上一段时间以后再决定删不删。
2. 删掉旧电脑的入站规则（管理员 PowerShell）：

```powershell
Remove-NetFirewallRule -DisplayName 'HouseholdRelay-HTTPS-8787'
```

3. 各客户端里旧的根证书可以留着，也可以按旧信任包里 README 写的撤销办法删掉；留着不影响新证书。

## 如果以后要换端口

外部端口和本机监听端口可以不同：外部端口是客户端地址里的那个数，本机监听端口是新电脑实际监听的那个数。

- 只换外部端口（例如外面改用 5433，里面仍是 8787）：改路由器映射的外部端口；客户端的 `ANTHROPIC_BASE_URL` 改成 `https://www.zkmryl.com:5433`；连接说明里的根地址要跟着改，在 HTTPS 页面按提示修改，会换证书的话按页面要求确认，并按第七节重装信任。
- 只换本机监听端口：路由器映射的内网端口、防火墙规则的端口和 HTTPS 页面的本机中转端口三处一起改，改完重启服务。客户端不用改。
- 管理页端口 8788 被占用时，启动命令加 `--admin-port 8789`，它只影响本机管理页地址。
