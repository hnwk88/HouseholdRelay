# 易用性 1/4：SQLite、网页首次设置与个人令牌

## 目标与前置

无前置订单。按总监方案 `docs/usability/ASSESSMENT.md` 和来源核查 `docs/usability/SOURCES.md` 实施。在保持单一活动上游的前提下，让管理员通过网页建立管理身份、设置项目配置、维护使用者及令牌，配置重启不丢失。

这张单完成管理及持久化基础；账户/API 网页直接配置、完整可信公网接入和个人用量由后续单交付。用户已明确直接填写上游地址及凭据，不以官方网页登录为前置。页面必须如实显示尚未实现/未接入的状态，不显示假的连接成功。

## 必须实施

1. 保持 .NET 10 Windows，增加 Razor Pages 和 Microsoft.Data.Sqlite，抽出配置/身份服务。无配置时启动本机首次设置页；不依赖本机已安装 Claude Code，不用伪造上游令牌或虚构客户端记录绕过校验。
2. 实现本机一次性引导、管理密码设置、管理登录/退出、初始化锁定和受保护管理路由。默认仅回环管理入口；校验 Host/Origin、CSRF、登录限速和 Cookie 属性；无管理认证及个人中转令牌均不能读取或修改管理数据。
3. SQLite 保存 schema 版本、配置、管理员、使用者、Token 版本和单一上游配置。WAL、外键、短事务及并发访问规则明确；不在转发网络等待期间持有数据库写事务。
4. 创建使用者、查看列表、改显示名、停用/启用及轮换个人令牌。使用者 ID 稳定，令牌哈希存储，明文仅在创建/轮换返回一次；首版每人一个有效令牌，最多 8 名使用者，已撤销版本不占名额。不要导出含全部令牌的默认目录。
5. 复用 ClientRegistry 的常量时间验证和 Admission 的限流/排队机制，改为按稳定 ID 绑定；管理写入提交后发布权限快照，失败不可半生效。停用/轮换返回成功后，新请求、排队后及上传完成后的旧令牌检查全部生效；已发出的请求可结束。
6. 迁移本项目既有 `.state/server.json`、DPAPI 凭据、证书及客户端哈希：保留旧令牌、启停状态、设备 ID 和身份对应关系；迁移前备份，事务失败可恢复，重复启动不重复导入。不能读取 Claude 官方登录文件。迁移账户信息不等于完成第 2 单的网页配置与真实调用验证。
7. CLI 与页面调用同一配置/令牌服务；SQLite 生效后停用 JSON 轮询覆盖路径，避免双写及并发管理丢更新。数据目录故障不能把已初始化的实例变成开放重置站点。
8. 对秘密字段只提供“已配置/未配置”等状态，密码、上游秘密、个人令牌均不回填列表或日志；错误信息可定位问题但不显示敏感内容。

## 验收证据

- 用干净目录实际启动页面，完成管理员设置、登录、创建甲乙两人、停用和轮换；重启后管理身份、配置和哈希仍可用。给出浏览器步骤及脱敏截图/记录，不只展示 API 测试。
- 使用旧格式夹具迁移，旧令牌继续可用、禁用令牌仍拒绝；重复迁移及注入迁移失败不会损坏旧数据。
- 未登录、个人令牌、伪造 Origin/CSRF 请求不能管理；两个初始化请求竞争只能成功一次；数据库无法打开时不会重新开放首次设置。
- 甲乙并发、令牌轮换、排队撤销和上传撤销都有实际请求验证；并发网页/CLI 修改没有丢更新。
- 原有 Release 构建和 10 项测试回归通过；新增测试覆盖上述状态变化和失败条件，避免仅复制实现断言。
- 交付完整命令输出、提交标识、页面步骤、已知限制，以及一处关键鉴权/迁移反例的可复现方法供总监独立检查。

## 边界与交付状态

不增加多账户号池、不开发 OAuth 登录、不升级为跨平台部署。账户/API 直接配置、用量及可信公网调用由后续订单完成；本单结束不能宣布总需求已完成。
