# 易用性 2/4：账户/API 直接配置、可信 HTTPS 与统一调用

## 目标与前置

前置：同批次“易用性 1/4：SQLite、网页首次设置与个人令牌”已验收。读取 `docs/usability/ASSESSMENT.md` 和 `SOURCES.md`，保持一个活动上游，让管理员在网页直接配置账户令牌或 API 密钥及上游地址，让使用者只配置中转地址和自己的令牌即可调用。用户已明确不需要官方支持，以实际可调用为准；不新增 OAuth 登录前置或等待平台授权声明。

## 必须实施

1. 网页提供账户/API 模式选择。账户模式填写上游地址及已有账户访问令牌，默认 Bearer，现有 Anthropic 预设使用 OAuth beta；兼容中转按明确设置决定 beta。API 模式填写上游地址及 API 密钥，默认 x-api-key，需要 Bearer 时明确选择。两种地址都允许兼容中转，地址与出站代理分开。API 模式不要求 Claude Code 安装，不附加 OAuth beta 或依赖账户设备归一。
2. 实现 URL 规范化与路径前缀保留，对根 URL、结尾 `/v1`、自定义前缀和 query 建立不歧义合同并显示最终请求地址。只接受管理配置的目的地址，默认 HTTPS，拒绝 URL 内嵌凭据及密钥查询串；不自动跳转，不关闭证书校验。管理员明确启用的回环/私网 HTTP 有范围限制和解析后地址检查。
3. 分别显示未配置、连通/TLS、鉴权、可用模型、最小调用和需重新接入等状态，并记录检测时间。模型目录缺失不误判为鉴权失败；实际模型请求成功才标记调用验证成功。真实测试有少量额度提示，诊断流量与个人业务量分开。
4. 候选配置测试后原子激活版本；旧活动请求使用原快照、新请求使用新快照，不能新 URL 混旧密钥。401/403 暂停、429 冷却按活动配置版本处理，诊断测试不改变正在服务的状态；继续不自动重放请求。账户凭据失效后支持网页重新填写、测试并恢复新版本；无法确定到期时间则显示未知，不声称自动刷新。两种模式切换后对外地址和个人令牌合同不变。
5. 完成可信证书网页导入或已有 HTTPS 反代接入；校验证书/域名/有效期，私钥受 DPAPI 保护。反代模式仅监听回环/受信网络并正确处理受信头；验证 SSE 不被缓冲。TCP 映射场景仍可直接终止 TLS。私有 CA 作为旧模式标识，不能冒充两项配置默认路径。
6. 连接说明页提供可复制的根地址、实际模型、默认推荐模型、Bearer/x-api-key 示例、Claude Code 两个变量的配置片段及非敏感错误排查。不回显已有个人令牌；创建时的一次性值可用于当前复制示例。
7. 保持 Messages JSON/SSE、Count Tokens、Models 和 HEAD 预热协议，保留 query、开放 beta、版本头、tool/thinking/cache 字段、ping 和结束事件。模型不支持的接口须明确说明；不将任意自定义 API 地址等同于跨协议转换。
8. 在普通及 SSE 错误、响应头和管理检测结果中消除上游秘密/账户凭据回显；脱敏不破坏正常错误类型及客户端能力降级语义。限制复制的响应头，保留必要 retry-after、x-should-retry、request-id 和适用的限流头；不回传 Set-Cookie 等敏感头。

## 验收证据

- 账户模式和 API 模式分别通过测试，覆盖账户 Bearer/OAuth beta 与 API x-api-key/适用的 Bearer 差异；下游个人令牌不会到达上游，上游凭据不会出现在下游请求样例、响应、页面和日志。
- 根 URL、`/v1`、前缀路径、错误端口、失效证书、跳转、401/403/429、缺模型目录、超时和配置切换都有实际请求测试。
- 使用干净 Claude Code 客户端，通过可信 HTTPS 只配置地址和个人令牌，完成非流式/流式调用及工具/会话场景；记录实际客户端版本，不依赖旧客户端包或私有 CA 注入。
- 提供经管理员在网页录入凭据后，对真实账户上游及真实 API 上游分别完成最小调用的证据，允许兼容中转地址；没有真实凭据时如实记录未实测，不把模拟结果写成真实通过。覆盖失效账户令牌更新、模式切换及重启后重新调用。
- 构造带秘密标记的 JSON 错误、SSE error 和响应头，确认无泄露；确认正常能力拒绝等错误仍被客户端正确识别。
- 证书配置、地址与凭据重启后仍在；保留权限/并发/取消/无重放回归。交付完整结果、提交标识、网页流程和失败反例复现步骤。

## 边界

外部 API 合同是 Anthropic Messages；不新增 Chat Completions、Responses、Bedrock/Vertex 协议转换、远程工具或多账户调度。账户凭据由管理员直接填写，本期不做 OAuth 注册、网页登录、Cookie 抓取、官方登录文件扫描或自动续期；用量与完整用户旅程由后续订单交付。
