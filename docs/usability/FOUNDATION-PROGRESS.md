# 管理与持久化基础实施记录

## 动手前十二问

当前工程台账仅有 UX-001、UX-002、UX-003。已逐条读取全文；查询“动手前十二问”未找到模板，以下按本单实际风险逐问记录，不假称引用了不存在的条目。

1. 解决什么问题？无配置时可启动本机网页，建立管理员、维护使用者和个人令牌，重启不丢配置。
2. 范围是谁决定的？当前已派任务书及 UX-001；本次交付管理和存储基础。
3. 前置满足吗？首张订单无前置，已认领并进入实施中；业务基线 9fff525，原有 docs 为总监未提交资料。
4. 哪些不属于本次？上游网页直接配置、可信公网入口和个人用量留给后续任务；界面必须如实呈现缺失状态。
5. 每项压在哪个现有机制上？令牌生成/哈希复用 ConfigurationFiles；固定时间鉴权和权限快照扩展 ClientRegistry；排队/限流复用 Admission 并改按稳定 ID；排队后/上传后撤销复用 RelayServer 二次鉴权；机密复用 WindowsSecrets 的 DPAPI 与 ACL；旧证书复用 Management 证书加载；CLI 和 Razor Pages 共用新增数据库及身份服务；迁移只读本项目旧文件。
6. 身份怎样关联？使用者、令牌版本、管理员及会话均使用主键；名称只作显示和旧 CLI 查询入口。
7. 数据怎样持久化？Microsoft.Data.Sqlite 固定版本，schema 版本、WAL、外键和短事务；网络转发期间不持有写事务。
8. 并发怎样保证？SQLite 串行提交管理写入，设置带版本冲突检查；令牌检查读取已提交权限快照，覆盖另一 CLI 进程的提交；不轮询 JSON。
9. 失败如何收场？迁移前保留原文件备份，导入事务回滚；独立实例标记防数据库遗失后自动重新初始化；错误时拒绝访问。
10. 秘密如何保护？管理员标准密码哈希，个人令牌仅返回一次、库内仅存哈希，上游/私钥 DPAPI；管理 Cookie、CSRF、Host/Origin 和限速一起验证。
11. 怎样证明？Release 构建、原十项回归及新增状态/失败测试，真实本机浏览器操作，迁移故障与跨进程管理/撤销请求验证；模型流量使用本机模拟上游。
12. 怎样交付？保留完整命令输出、脱敏页面记录、独立复现步骤和提交标识；追加结果后转待验收，仅推进本单。
