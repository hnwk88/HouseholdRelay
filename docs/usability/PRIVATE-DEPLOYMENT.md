# 私人部署、客户端信任与恢复

当前路线是 Windows 服务主机、已有的 Anthropic Messages 兼容 API、每台私人电脑一次性安装 CA。日常管理全部通过本机网页完成。官方账户及公网部署以后按实际需要安排；本程序不会自动登录官方账户、购买域名或配置公网映射。

## 首次启动

把发布包解压到可写的固定目录。框架依赖包需要 ASP.NET Core Runtime 10 x64；自包含 win-x64 包已带运行时。使用稳定的 Windows 用户启动，数据目录建议与程序版本目录分开：

```powershell
.\HouseholdRelay.exe serve --home D:\RelayData
```

保持此窗口运行；用 Ctrl+C 正常停止。双击程序也可启动，默认数据目录为程序所在目录。管理页默认 `http://127.0.0.1:8788`，仅服务主机本机能访问；个人中转入口是另一个 HTTPS 端口。端口冲突时用 `--admin-port 8789` 更换管理端口。

1. 打开启动窗口给出的本机管理地址，输入该窗口显示的引导码，设置至少 12 字符的管理密码。引导码不要放进网址或共享日志。
2. 登录“上游接入”，选择 API 密钥、提供商预设、上游根地址、认证方式及模型，填写上游密钥后保存候选。
3. 确认最小调用会产生少量上游消耗，执行检测，通过后激活。仅接受原生 Claude Code 请求的上游应选择“Claude Code 实际调用”；该检测要求服务主机安装原生客户端。标准检测不要求安装客户端。
4. 在“HTTPS 入口 → 私人设备”填写 HTTPS 根地址和本机中转端口，创建证书。按下节选地址，不能把 `localhost` 发给其他电脑作为服务地址。
5. 正常停止并重新运行相同启动命令。HTTPS 页面应显示监听已启动，证书名称和有效期正确。
6. 在“连接说明”下载公共信任包，按下一节为客户端安装信任。
7. 在“使用者与令牌”为每个人创建身份。令牌仅在创建或轮换成功时显示一次，分别交给本人；不要给使用者上游密钥或管理密码。

候选检测失败不会替换当前活动配置，也不会自动改认证或重试生成。上游失效后网页保存新候选、测试、激活即可恢复，日常不编辑配置文件。

## 主机、地址、端口与证书

| 使用位置 | HTTPS 根地址示例 | 部署要求 |
| --- | --- | --- |
| 服务主机本机 | `https://localhost:8787` | 用于本机试用；其他电脑的 localhost 指向自己 |
| 同一局域网的电脑 | `https://192.168.1.20:8787` | 主机地址稳定，网络和防火墙允许访问此端口 |
| 已有主机名 | `https://relay.home.example:8787` | 客户端能解析到正确主机，证书 SAN 与名称匹配 |
| 以后通过公网 TCP 映射 | `https://relay.example.com:5433` | 自行配置 DNS 和 TCP 映射到主机 8787；名称与证书匹配 |

根地址填客户端实际访问的地址，本机监听端口填服务主机绑定的端口。两者端口可以不同。私有 CA 只解决证书信任，不解决网络可达。管理端口不要映射到外网。

创建私有证书会签发本实例的独立根和叶证书。CA 私钥签发后即释放，不保存或分发；服务器私钥由当前 Windows 用户 DPAPI 加密保存。更换地址名称或重新创建证书会换根，网页要求明确确认，每台客户端需重新核验指纹和安装。叶证书当前有效期两年，根五年，以页面实际时间为准；到期前安排更新。

以后需要免逐台安装时，可使用公网可信 CA 签发的证书，在网页导入含私钥和中间链的 PFX。导入验证系统信任与吊销状态，仍需准备 DNS、网络入口和客户端可达性。反向代理若自行部署，应保留正常校验并关闭 SSE 缓冲；本版本未提供代理管理向导，不信任代理头来开放管理入口。

## 每台 Windows 电脑的一次性信任

管理员从连接页发放 `HouseholdRelay-client-trust.zip`，另行告知页面显示的 CA SHA-256 指纹。客户端包应当只有 `relay-ca.pem`、`Install-RelayTrust.ps1` 和 `README.txt`；不能包含 `.state`、PFX、私钥或任何人的令牌。

1. 解压并核对来源、指纹，阅读安装脚本。如果下载文件被 Windows 标记，核验后在文件属性中解除锁定。执行策略受组织管理时遵循现有策略，不关闭 TLS 校验。
2. 在包目录 PowerShell 执行连接页给出的命令：

```powershell
.\Install-RelayTrust.ps1 -ExpectedSha256 管理员提供的64位指纹
```

3. Windows 可能弹出根证书安全确认。核对证书后确认，取消不会完成信任安装。脚本只修改当前 Windows 用户的根信任，并把公共 CA 与已有的额外 CA 合并到本机用户目录，配置用户级 `NODE_EXTRA_CA_CERTS`。
4. 完全退出并重新打开终端、Claude Code 和浏览器。已启动的终端父进程可能保留旧环境；当前 PowerShell 可以显式刷新这一项：

```powershell
$env:NODE_EXTRA_CA_CERTS = [Environment]::GetEnvironmentVariable('NODE_EXTRA_CA_CERTS', 'User')
```

5. 在浏览器打开 HTTPS 根地址下的 `/healthz`，不应有证书警告。再执行 Claude Code 最小会话，确认该客户端确实继承额外 CA。浏览器通过不能替代 Claude Code 验证。

每个 Windows 用户各装一次。其他操作系统及其他客户端的信任存储需要单独验证，不能按本次 Windows 结果宣称全兼容。不要使用 `-k`、`--insecure` 或 `NODE_TLS_REJECT_UNAUTHORIZED=0`。

撤销方法和原环境记录位置见包内 README。测试安装会在测试结束时撤销该测试根并恢复原用户变量；正式使用的 CA 由设备使用者管理。

## 日常使用与管理

每次使用在客户端终端设置连接页的两项变量；个人令牌避免写入共享脚本和命令历史。可通过隐藏输入在当前终端赋值：

```powershell
$env:ANTHROPIC_BASE_URL = 'https://你的中转主机:8787'
$relayCredential = Get-Credential -UserName 'relay' -Message '密码栏填写自己的个人中转令牌'
$env:ANTHROPIC_AUTH_TOKEN = $relayCredential.GetNetworkCredential().Password
claude --model 管理员推荐且实测通过的模型
```

Get-Credential 的用户名不参与中转身份判定。客户端已有其他 Anthropic API、账户认证、云厂商模式或代理变量时，应按其设置清理冲突。不要同时配置相互冲突的认证方式。首次部署可用独立终端和独立 Claude Code 配置目录进行检查；不会读取或借用官方账户登录材料。

支持协议是 Anthropic Messages；不是 OpenAI Chat Completions/Responses。连接页显示已检测模型和模型目录；实际可用性由上游决定。Count Tokens 和 Models 未提供时不能伪装成功。具体客户端和版本的证据见验证记录。

管理员可以在网页新建、改名、轮换、停用使用者，以及切换已经检测过的单一活动上游。轮换与改名保持历史归属，旧令牌立即失效；停用后无法调用或查询个人用量。已发往上游的请求允许结束并归原人，排队和上传中的撤销会在发送前被拒绝。

个人打开 HTTPS 根地址下的 `/my-usage`，输入自己的令牌查询；令牌不进入 URL 或浏览器存储。管理员“用量”页可按人、接口、模型、结果、时间区间查询，按小时或天汇总。空状态明确显示无记录；输入/输出/缓存 Token 和金额未知时显示未知。估算费率必须由管理员有依据填写，按发送时快照计算，改价不追溯历史。币种和来源分开合计；金额未知不代表免费。

## 备份、升级与回退

1. Ctrl+C 正常停止服务，确认进程退出。复制 `--home` 下完整 `.state` 及同级 `.relay-instance` 到受控备份目录，不只拷贝运行中的 relay.db；WAL 可能还有提交数据。
2. 记录程序版本、Windows 用户、数据目录、HTTPS 地址和公开 CA 指纹，保留旧程序包。备份含受保护的秘密，不分发给客户端。
3. 将新程序解压到新版本目录，以相同 Windows 用户、相同 `--home` 启动。数据库迁移按事务执行；旧 JSON 只在初次迁移前备份一次，以后不再作为配置来源。
4. 登录检查使用者启停状态、用量、证书、上游配置；执行一条自己的合成最小调用。若迁移或完整性失败，保留失败现场并恢复配套备份，不能删除数据库或实例标记来重新开放首次设置。
5. 回退时停止新版本，用升级前的程序包和完整数据备份成套恢复。不要拿旧程序强行打开新 schema，也不要混用不同实例的标记、数据库或密钥目录。回退会失去备份后产生的用量和配置变更，先保存当前完整副本。

当前 schema 为 v3，本次私人 CA 功能复用既有表，没有新增格式版本。v1/v2 启动会升级到 v3；不支持该版本的旧程序会拒绝。Windows DPAPI 绑定运行身份，换 Windows 用户或另一台电脑不能保证解密。当前没有跨身份迁移工具；同机同用户恢复是已支持路线，换机应另行规划重新接入和分发，不能通过复制数据库冒充已恢复。

正常停服排空后保存结束记录；意外退出遗留的记录在启动时标为中断/不完整。服务同一实例只允许运行一份。清理按 UTC 请求开始时间滚动保留 40 × 24 小时，严格早于边界才删，启动和每小时分批执行；身份、配置和费率不随用量删除。统计始终过滤窗口，停机跨过清理时点后再次启动也会清理。

## 故障定位和试运行观察

| 现象 | 检查及处理 |
| --- | --- |
| 浏览器证书警告 | 核对根指纹、当前用户信任、访问名称及有效期；更新后重启，不绕过校验 |
| 浏览器可用、Claude Code 报证书错误 | 新终端检查 NODE_EXTRA_CA_CERTS 是否指向存在的公共 CA 文件，刷新用户环境并重启客户端 |
| 连接拒绝或超时 | 主机程序是否运行、正确监听端口、客户端解析、网络、防火墙、TCP 映射；不要把管理地址当 API 根地址 |
| 401 | 个人令牌是否正确、轮换或停用；不以管理密码代替 |
| 503 上游认证暂停 | 管理员网页替换凭据、测试后激活；不自动重放原请求 |
| 429 | 按 Retry-After 等待，共享上游冷却及并发限制；不要通过改名或轮换规避 |
| 502/504 | 上游地址、代理、TLS、协议或超时；保留 request_id 和时间，不粘贴秘密或请求正文 |
| 用量未知/部分 | 检查上游是否返回 usage、流是否完整；不要补零，估算请求也不能冒充推理 Token |
| 数据库错误 | 检查空间、锁占用、权限及运行身份；起始保存失败不会发给上游，结束保存失败会提示并记录元数据 |
| 引导码或登录无效 | 核对本机管理端口和实例；频繁失败会限速，等一分钟；已初始化实例不会重新开放设置 |

试运行时记录启动和重启时间、客户端版本、上游版本、错误状态、request_id、用量完整性以及资源占用。任务管理器可观察进程 CPU、工作集与峰值；性能异常时记录同一时段的并发和请求耗时。用量页检查按人的累计和缺失数量，服务控制台查看 `usage_storage_failure` 等元数据事件。不要收集提示词、回答、密码、个人令牌或上游秘密。

真实工具会话曾在前次验收首轮出现最终回复标记不符合预期，复核通过但根因未确定。本次合成验收脚本保留阶段、工具回合、进程退出状态及必要脱敏诊断，失败不自动重试或放宽断言。实际试运行继续观察工具是否确实执行、结果是否符合预期。试运行期限及是否接官方账户由用户根据体验决定。
