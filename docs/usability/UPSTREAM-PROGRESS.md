# 上游接入与可信 HTTPS 实施进度

## 动手前十二问

1. 解决什么问题？管理员通过网页填写账户令牌或 API 密钥、测试并激活单一上游，使用者凭固定中转地址及个人令牌调用。
2. 范围依据是什么？当前任务书与已读取的 UX-001、UX-002、UX-003 全文；外部合同保持 Anthropic Messages。
3. 前置满足吗？管理与持久化基础已验收，当前任务已派出、认领并进入实施中，代码基线 e8d3878。
4. 哪些不属于本次？OAuth 登录、多账户调度、其他 API 协议转换与个人用量不在本次。
5. 每项压在哪个现有机制上？SQLite 短事务及 schema 版本扩展候选/活动上游；WindowsSecrets DPAPI 保存凭据与证书；ConfigurationService 保留设置/CLI 统一入口；RelayServer 继续承担协议白名单和撤销边界；ClientRegistry 与 Admission 保持个人鉴权、排队和并发；新增上游连接模块承接原 HttpClient、认证头、暂停/冷却；标准 X509Chain/主机名检查验证证书；Razor Pages 复用现有管理认证、CSRF 与页面样式。
6. 关联怎样建立？候选配置有不可变主键，测试结果关联同一候选，激活核验预期活动版本；请求持有同一上游版本的完整快照。
7. 数据怎样持久化？schema 升级在事务内完成，旧活动配置可迁移；候选和诊断结果持久化，所有秘密只保存 DPAPI 密文。
8. 并发怎样保证？候选内容不可变，测试与激活按主键和状态更新；激活用版本冲突检查；活动请求持有旧连接租约，新请求读取新版本，旧版本暂停不影响新版本。
9. 失败怎样处理？测试失败不能激活；拒绝跳转和不可信 TLS；仅管理员明确允许的回环/私网地址可使用 HTTP，DNS 结果检查后按地址连接，失败不自动重放。
10. 秘密怎样保护？凭据不回填页面，错误只保留必要协议语义；响应头白名单、结构化 JSON/SSE 脱敏、诊断只保存安全状态，证书私钥和密码不出现在日志。
11. 怎样证明？Release 与全量回归；真实本机 HTTP/TLS 的模式/前缀/切换/错误/泄露/故障测试；无窗口浏览器配置旅程；真实上游和可信入口条件已向用户询问，缺失时单列未实测。
12. 怎样交付？保存完整输出、浏览器步骤、脱敏截图与反例，提交代码并记录标识，再交回待验收。

## 初始实施选择

可信入口采用网页导入 PFX 证书并由现有 Kestrel 终止 TLS，支持现有 TCP 映射；按系统信任链、域名、用途及有效期验证，不自动安装根证书。证书/监听端口变更明确提示重启。上游配置采用保存候选、确认少量调用费用后测试、测试成功再激活的流程。

当前正在扩展存储和上游连接模块。后续依次接入网页、完成协议与错误脱敏回归、浏览器验证和交付记录。
