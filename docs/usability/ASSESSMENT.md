# HouseholdRelay 易用性改造评估与实施方案

日期：2026-10-28。角色：总监。代码基线：`9fff525`。本轮核查了全部业务源文件、测试工程和官方接入文档，重新构建并运行了现有测试；本轮交付是方案、台账和订单，不是功能实现或功能验收。

## 1. 结论与定位

现有转发核心可以复用，改造需要补上管理入口、持久化身份、可配置上游、可信 HTTPS 接入、用量采集及查询，不能只在现有命令外加一层网页。

保持“单账户号池”：一个部署实例只有一个生效的上游身份及连接配置，多名使用者持各自的中转令牌，共享这个上游的额度、并发和冷却限制。账户和 API 是两种接入方式，切换时替换生效配置；不增加多账户轮询、自动换号、故障切号、售卖额度或复杂租户体系。

根据当前项目实际用途，首个明确支持的客户端是 **Claude Code，外部协议为 Anthropic Messages**。其他能配置该协议、地址和认证头的客户端须按兼容矩阵逐个验证。不能把“可配置 API 地址”写成“兼容任意 API 协议”。

账户和 API 两种方式均采用网页直接配置：账户模式填写上游地址与已有账户访问令牌，API 模式填写上游地址与 API 密钥。用户本轮明确要求“直接配置，不需要官方支持，只要能调用”，因此不把官方网页登录、第三方 OAuth 注册或平台支持声明设为实施前置。两种方式都显示状态并测试实际调用；模拟成功不能代替真实上游成功。

## 3. 网页体验与部署边界

采用 ASP.NET Core Razor Pages，静态资源随发布包提供。首版不引入单独的 Node 构建链和前后端部署。

管理员旅程：启动发布程序 → 打开本机首次设置页 → 设置管理密码 → 设置对外地址和 HTTPS 方式 → 配置并测试上游 → 新建使用者并发放个人令牌 → 复制调用说明 → 查询用量、停用/更换令牌。

页面划分为首次设置、概览、上游接入、使用者与令牌、用量、连接说明。表单使用中文标签、明确错误定位、键盘可操作控件和复制成功提示；秘密字段不回填原值。用户调用不需要管理密码，管理会话不能作为中转令牌。

新安装允许“无上游、无使用者”状态，页面显示尚未配置，模型调用返回明确的未就绪错误；不填假令牌绕过现有 Validate。初始化完成后锁定首次设置流程。数据库故障或遗失不能自动暴露一个可被远程抢占的重置入口。

首次设置仅绑定回环地址，以本机一次性引导凭据防抢占，并校验 Host/Origin。远程管理须由管理员明确启用且使用可信 HTTPS。管理认证采用标准密码哈希和 Cookie 会话，保护状态变更的 CSRF、登录限速、退出及会话失效；中转令牌不能访问管理接口。管理员可查所有人的用量；个人查询入口只能按已验证令牌推导使用者，不信任 URL 中传来的使用者 ID。

“只填地址＋令牌”约束的是使用者：平台和模型作为连接说明中的固定选择，默认模型由管理员验证并推荐。Claude Code 页面生成 `ANTHROPIC_BASE_URL` 与 `ANTHROPIC_AUTH_TOKEN` 的配置片段；有 GUI 的兼容客户端提供对应的地址和令牌字段说明。若某个客户端自身只能通过设置文件或环境变量配置，网页提供可复制/下载的示例，不宣称第三方客户端已有填写网页。

对外 HTTPS 两条可交付路径：管理员在网页导入匹配域名的可信证书，继续使用现有 TCP 映射；或接入已经部署的 HTTPS 反向代理，中转只监听回环/明确受信的内部地址，并验证代理不缓冲 SSE。证书私钥受 DPAPI 保护，页面显示域名、有效期和检测结果。旧私有 CA 路径明确标为需要额外信任配置，不能拿它通过“两项配置”验收。

发布程序启动、取得域名/公网入口及可信证书是一次性部署前提。网页负责本项目内的配置和检测；没有域名、证书或公网映射时，不能仅保存一个 URL 就显示“已可用”。本期不把自动控制花生壳、防火墙、DNS 或自动签发任意域名证书列为交付承诺。

## 4. 存储与身份决策

- 使用 `Microsoft.Data.Sqlite`，固定兼容 .NET 10 的稳定包版本并记录依赖。数据库放在受 ACL 保护的 `.state` 数据目录，与凭据保护文件同属本次部署；不是 MyCoAI 领航员的本机数据库。
- 逻辑实体：系统设置及 schema 版本、管理员身份、使用者、令牌版本、单一上游配置及版本、逐请求用量。用量不保存提示词、模型输出、完整请求/响应、Cookie 或凭据。
- 使用者使用不可变 ID，名称只是显示字段。每人首版一个有效令牌，令牌轮换生成新版本并撤销旧版本，历史用量仍指向同一使用者。历史令牌记录不占新增使用者名额。
- 个人令牌只在创建/轮换成功时展示一次；数据库只存哈希及非机密标识。不生成带所有人明文令牌的默认客户端目录，不把秘密放到 URL、localStorage 或分析事件中。
- 上游凭据和证书私钥继续使用当前 Windows 用户的 DPAPI；管理密码使用标准带盐密码哈希。备份到另一 Windows 身份并不保证可解密，恢复页面要明确要求重新接入凭据。
- SQLite 启用外键、WAL、合理忙等待及短事务。网络流式请求不得持有写事务；发布前覆盖并发调用与网页写配置竞争。每次 schema 迁移有版本、事务和失败恢复证据。
- 旧版迁移仅读取管理员指定的本项目数据目录：保留已有 TokenHash、启停状态、设备 ID、证书和凭据；原设备名称默认成为使用者名称并在网页解释。先备份、再迁移、重复启动不重复导入；不能自动读取官方 Claude 登录文件。
- SQLite 生效后，旧管理命令调用同一服务，不再与 JSON 双写竞争；旧配置文件留作明确标记的备份，不继续轮询覆盖数据库。旧令牌继续有效，不强迫所有人重新分发。

## 5. 上游接入与协议边界

### API 接入

管理员输入 Anthropic Messages 兼容 API 的根地址和密钥。页面展示最终请求 URL，避免根路径、`/v1` 和供应商路径前缀拼接歧义；对根地址和已带 `/v1` 的输入采用明确、可测试的规范化规则。当前 `new Uri(base, absolutePath)` 会丢弃自定义路径前缀，不能原样用于新功能。

默认 HTTPS、证书正常校验、不跟随跳转；禁止 URL 内嵌密码、查询串密钥和由使用者请求指定上游。回环/私网 HTTP 仅作为管理员明确配置的本地部署选项，限制目的地址与重定向，测试中覆盖 DNS 解析后地址校验，避免新增的连接测试成为任意内网请求入口。上游代理与上游 API 地址是两个不同字段。

API 模式默认使用上游 `x-api-key`；确有 Anthropic 兼容提供商要求 Bearer 时，作为显式配置选项验证。下游只使用个人中转令牌，不透传下游 Authorization、x-api-key、Cookie。API 模式不附加订阅 OAuth beta，不要求本机存在 Claude Code，不套用账户设备元数据归一来判断可用性。

测试分为连通/TLS、鉴权/模型发现、最小模型调用。仅连通或 `/healthz` 成功不能显示模型已可用；模型列表不支持与密钥无效分开呈现。页面发起的真实模型测试须提示可能消耗少量上游额度，记为管理员诊断流量，不混入个人业务用量。

修改先保存候选并测试，通过后原子激活新版本；活动请求保持原版本，后续请求使用新版本，不混用新地址和旧密钥。旧版本的 401 暂停不能污染新版本；诊断测试也不能改变正在服务的版本。并发、暂停和冷却仍是单一活动上游范围。

### 账户令牌直接配置

当前可复用能力是已有账户访问令牌的 Bearer 转发。管理员在网页粘贴自己取得的访问令牌，选择账户模式，填写上游地址并测试；默认地址为现有 Anthropic 地址，也可配置兼容的中转地址。账户令牌与 API 密钥在界面和存储类型上区分，与个人中转令牌完全分开。

默认 Anthropic 账户预设沿用现有 Bearer 和 OAuth beta 行为；兼容中转是否需要该 beta 由明确的接入预设/设置决定，API 模式不硬加。保留版本和其他语义 beta，不能为“账号可用”伪造调用成功或仅依据字符串前缀判定令牌有效。

页面显示未配置、待测试、调用成功、鉴权失败、连接失败、冷却等状态及最后测试时间。401/403 给出更换令牌的操作入口，网页保存新凭据并验证后恢复新版本，无需日常手改文件或重启。无法从凭据可靠取得到期信息时显示“到期时间未知”，不声称自动续期；首版以手工替换访问令牌处理失效。

这一路径实现“直接配置”，不新增账户密码登录、OAuth 注册/回调、浏览器 Cookie 抓取、自动读取官方客户端登录文件或自动刷新。官方资料的核查结果作为实现能力说明保留在 SOURCES；按用户最新决定，官方支持不是本期派单前置。接通与否以所配地址、凭据和模型的真实请求为准，未验证显示未验证。

## 6. 用量口径、持久化与保留期

每个通过个人令牌鉴权的受支持 API 请求分配 request_id，在转发前提交一条起始记录；记录不可变 user_id、token_id、配置版本、开始时间、接口类别、请求模型。结束后更新状态、上游状态码、耗时和用量；同一个 request_id 唯一，更新幂等。客户端自行重试是另一次请求，服务端不自动重放。

请求数按调用次数统计，分别列出推理、估算、模型查询及成功/失败/取消；管理诊断、健康检查、静态页面、预热和无法鉴权的请求不混入个人模型消耗。鉴权后被限流/排队/上传拒绝的请求记为该人的失败，标明未发往上游。不能信任请求体中的姓名、metadata 或客户端自报 Token 数进行归属。

输入/输出 Token 使用可空整数，并携带用量完整性：完整、部分、上游未提供、不适用。服务端确知尚未发往上游时显示“不适用/未发送”，不能把一次没有拿到最终用量的上游请求显示为零消耗。

JSON 从 usage 获取用量；SSE 从 message_start 取得起始信息，按 message_delta 的累计语义更新最终值，不能把多个累计 output_tokens 相加。缓存写入/读取 Token 若存在则单列并解释口径。未知字段和事件不得使正常流式响应失败；解析缓存有界，覆盖跨网络分片、UTF-8 分片和大事件，不能为统计缓存整个回答。中途取消或断流保留已知部分并标记不完整，不推算最终输出。

查询展示“已知 Token 合计＋缺失/不完整的请求数”。全部未知时合计显示“未知”，即使 SQL SUM 得到 NULL 也不能转成 0；混合数据不得把已知合计标成完整总量。不存储提示词和回答来事后补算，也不把 count_tokens 的估算结果计入模型实际消耗。

数据库插入起始记录失败时，拒绝尚未发出的请求并返回可诊断错误。结束写入使用独立于客户端取消的有界持久化流程；写入失败可见、可重试，不静默丢弃。异常终止后遗留的 started 记录在启动恢复时标成中断/用量不完整，不能伪造成功或零消耗。正常重启须完整保留已结束请求。

默认保留滚动 **40 × 24 小时**。按 UTC 的 request_started_at 判断，删除严格早于 `now_utc - 40 days` 的记录，恰好处于边界的保留；页面按用户时区展示。启动清理后提供查询，运行中至少每小时批量清理；查询本身始终限制在保留窗口，避免等待下一轮清理时展示过期数据。明细及持久化汇总遵守同一窗口，账号、Token、配置不随用量清理删除。测试注入时钟覆盖边界，不等待真实 40 天。

## 8. 最终验收证据

1. 新数据目录启动，使用网页完成管理密码、可信对外地址、上游接入和个人令牌创建；在干净客户端只配置地址与个人令牌即可实际调用，不依赖旧客户端包/私有 CA 注入；保存脱敏的页面步骤和结果。
2. API 模式用真实 API 密钥，账户模式用真实账户访问令牌，分别在网页直接配置后完成非流式及流式调用；可使用兼容中转地址。分别记录提供商/接入方式、客户端版本、模型、状态、request_id 和用量结果，不记录秘密。没有实际凭据时如实标记尚未实测，不能拿一种模式代替另一种。
3. 甲乙两人并发调用，使用者不能伪造归属；轮换仍累计到原人，旧令牌/停用令牌的后续、排队和上传中请求被拒绝；已经发往上游的请求允许结束并归原人。
4. 正常重启后配置、哈希、启停状态及用量不丢；模拟意外退出可识别未结束请求；用固定时钟验证 40 天前、边界点、40 天内以及服务停机跨过清理时点的记录。
5. 上游省略 usage、仅有部分 usage、SSE 分片及取消时仍显示正确完整性；累计值不得重复相加，健康检查/估算不充当推理消耗。
6. 页面、管理 API、普通及 SSE 错误、响应头、日志、备份/下载样例均用虚构秘密标记做泄露检查；越权、CSRF、初始设置抢占及设置竞态有反例。保留 Claude Code 对正常上游错误的必要兼容性。
7. 每单交付构建与相关测试完整输出、可复现步骤及提交标识；总监复跑并对关键路径做一次受控反例检验，不能仅凭工程师总结通过。最终文档逐项标明真实上游测试与本地模拟测试。
