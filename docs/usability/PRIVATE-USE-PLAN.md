# 私人使用、私有 CA 与官方账户接入时机

决定日期：2026-10-28。依据：用户明确选择“每台电脑安装一下证书就能用”，要求先把程序做完整并试运行，确认好用稳定之后再接官方账户；公网域名部署也留到程序可用后按需处理。

本决定取代 UX-001、订单 61—63 及此前阶段安排中与下述内容冲突的要求。61 已完成的阶段验收有效，62 按原顺序继续实施。

## 当前交付路线

1. **面向私人设备，采用私有 CA。** 每台电脑进行一次证书安装与信任准备，之后日常通过中转地址和个人令牌使用。证书准备可以包含目标客户端实际需要的 CA 信任配置，由安装引导或清晰步骤完成；不能只验证浏览器信任便宣称 Claude Code 已能用。
2. **先使用现有两家 API 上游。** 完成用量功能、网页管理、持久化与 40 天清理，再用真实 API、私有 CA HTTPS 及真实客户端走完整旅程，交付可供私人试运行的版本。
3. **官方账户在试运行之后再接。** 先由用户使用一段时间，确认体验和稳定性，再安排官方账户接入。试运行时长由实际使用决定，不预设几天后自动启用。当前不要求用户提供官方账户材料，不做官方登录、令牌读取或真实账户请求；账户分支仍保留模拟回归和凭据隔离验证。
4. **公网部署后置。** 可以先在自己的电脑或指定主机运行，客户端通过可达地址访问；需要外网访问时，再配置域名解析和入口。公网可信 CA 证书是免逐台安装信任的可选路线，不是当前私人版本交付前置。域名访问、网络可达和 HTTPS 证书是不同的部署事项，也与官方账户接入不同。

## 63 的当前验收范围

63 在 62 已验收后，完成真实 API + 私有 CA HTTPS 的完整网页及客户端旅程，包含两位使用者、JSON/SSE、工具会话、用量归属、令牌轮换和停用、重启与清理、错误与秘密隔离、实际客户端信任配置及部署文档。通过后可以交给用户试运行，不再以公网可信证书或真实官方账户作为当前版本的硬验收前置。

“一次性证书安装完成后，日常只配置地址和个人令牌”是用户本轮接受的使用合同，替代原来“不依赖私有 CA 注入”的要求。私有 CA 作为当前选定方案呈现，不应继续在界面或说明中被写成不满足用户要求的淘汰路线。具体所需页面、引导和文档调整归 63 处理，不扩大 62 的实现范围。

客户端只获得 CA 公共证书和自己的中转令牌，CA 私钥及服务端私钥仍由服务端保护。验证证书信任、地址匹配及有效期，保留正常 TLS 校验；用关闭校验代替安装信任不符合此方案。

真实官方账户及公网部署继续明确记录为后续事项，不宣称已经实测。官方账户接入前以本次试运行结果和用户当时的安排为准；程序回归通过不构成账号风险为零的保证。
