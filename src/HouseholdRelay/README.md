# Household Relay — C# 家用中转

一个部署实例可以保存多家上游（API 供应商、兼容中转的账户令牌、官方账户），同一时刻有一家在用；多名使用者持各自的个人令牌调用。当前协议为 Anthropic Messages，客户端为 Claude Code。不做多账户轮询：只有打开「自动切换」后，在用的那家失败时才按顺序换到下一家测试通过的上游。

当前版本提供：**本机网页管理、SQLite 持久化、个人令牌、多家上游的检测与切换、失败自动切换（带总开关）、上游加密导出与导入、官方账户登录（含重新登录）与导入登录文件、思域、按已保存上游与模型计价、个人用量与金额及滚动 40 天清理、网页私有 CA、客户端公共信任包、证书导入**。每台 Windows 电脑安装一次信任，日常只配置中转地址和个人令牌。完整步骤见[私人部署与恢复](../../docs/usability/PRIVATE-DEPLOYMENT.md)，换电脑见[搬到另一台电脑](../../docs/usability/MOVE-TO-ANOTHER-PC.md)。

## 启动管理页

需要 Windows 和 ASP.NET Core Runtime 10 x64（安装 .NET 10 SDK 也可以）。把发布程序放在可写目录后运行：

```powershell
.\HouseholdRelay.exe serve --home D:\RelayData
```

不带参数启动也会运行服务，默认数据目录是程序所在目录。新安装不要求安装 Claude Code，也不要求先填写上游凭据。

1. 在同一台电脑打开 `http://127.0.0.1:8788`。
2. 把启动窗口显示的本机引导码填入页面，设置至少 12 个字符的管理密码。
3. 进入「上游接入」添加上游。API 供应商只填名称、地址、密钥三样，认证方式和检测方式默认自动判断，按「获取模型」读取模型目录（不花额度）；官方账户按「登录官方账户」或「导入登录文件」。然后在上游列表里打开这一家的菜单，「选择模型并测试」（会消耗少量额度），通过后「切换到这一家」。
4. 进入「HTTPS 入口 → 私人设备」，填写客户端可达的 HTTPS 根地址和本机监听端口，创建私有 CA 与服务器证书。重启服务；本机试用可用 `https://localhost:8787`，其他电脑需使用主机的局域网地址或可解析名称。
5. 在「连接说明」下载公共信任包，逐台核对 CA 指纹并安装当前用户系统信任及 Claude Code 额外 CA。Windows 可能要求确认根证书；完成后完全退出并重新打开终端和客户端。
6. 进入「使用者与令牌」为每个人生成令牌，在「连接说明」复制中转根地址和示例，选择实际测试过的模型。先检查 HTTPS `/healthz`，再验证 Claude Code 实际调用。
7. 「项目设置」可调整上游代理、转发限制和思域；监听端口、思域、证书及转发限制需重启，网页切换上游和个人权限立即生效。

引导码仅在本机启动窗口显示，不放进网址。首次设置成功后锁定该入口。管理密码与个人令牌分别用于管理和调用，不能互换。管理页只监听 IPv4 回环地址，不能从远程、花生壳或代理访问；可用 `--admin-port 8788` 改管理端口。

个人令牌只在创建/轮换成功时显示一次，不回填列表、不存入浏览器存储，不默认导出所有人的客户端包。最多 8 名使用者，每人一个有效令牌。停用和轮换会立即阻止新请求，以及仍在排队或上传的请求；已发往上游的请求可以结束。轮换不会重新启用已停用的使用者。

## 上游接入

上游列表里每家一个按钮，读作「名称，状态」，按下打开这一家的菜单：切换到这一家、查看这一家的用量、重新登录（只对登录得到的官方账户）、选择模型并测试、重新获取模型、改名、导出、删除。菜单里只出现这一家此刻能做的事。

- **检测**：只有有效的 Anthropic Messages 回复才算测试通过；连通、模型目录返回或单独 HTTP 200 都不算。检测方式默认自动判断：先发一次标准 Messages 调用，没通过（401、429 除外）且服务所在电脑装有原生 Claude Code 时，再做一次「Claude Code 实际调用」（在独立目录禁用工具做一次真实调用，上游凭据留在中转进程内）；官方账户只做实际调用。也可以在高级设置里手动指定，结果会注明「手动指定」。检测在后台跑，离开页面不中断；失败不改在用的上游，不自动重放生成请求。
- **自动切换**：上游页的开关。打开后，在用的那家失败时按顺序换到下一家测试通过的上游，每次尝试都留记录，用量页读得出这次实际走的哪家、为什么失败。它会把请求交给另一家可能计费的上游，所以新建实例默认关；已有实例的开关保持原样。
- **官方账户**：按「登录官方账户」后，程序委托本机 Claude Code 打开浏览器登录，凭据只存在数据目录 `.state\official-accounts` 下，不碰本机 Claude Code 自己的登录。也可以导入另一台电脑登录过的 `.credentials.json`，导入后那份登录只给中转用。凭据过期时在菜单里「重新登录」：核对是同一个账户才换上新凭据，这一家的主键与思域绑定不变；登成别的账户会被拒绝，原凭据不动。发往官方的请求按本机原生 Claude Code 的客户端身份发出，取不到时本地拒绝。
- **导出与导入**：把勾选的上游连同密钥用当场设的密码加密成一个文件，拷到另一套中转导入。密码不保存，忘了就解不开。登录得到的官方账户导出即搬走：本机不再用它转发、不再续期。
- **删除**：要先勾确认；在用的那家和正在检测的不能删。删掉的上游清掉加密凭据、不再出现在列表里，历史用量仍归原来那家。

上游密钥不回填，过期时间未知，不自动续期（官方账户由本机 Claude Code 刷新）。两个浏览器同时更改在用的上游时，后到的那次会提示冲突。

已实测 `https://aitoll.net/v1/cc` 使用 API/Bearer/Claude Code 检测，`https://api.sftoken.top` 使用 API/x-api-key/标准检测，模型均为 `claude-opus-5-5`；适用范围及复现见[兼容性整改验证](../../docs/usability/UPSTREAM-REWORK-VALIDATION.md)。

## 思域

思域是 MyCoAI 里经中转使用官方账户的启动方式。在「项目设置」勾上「接受新的思域会话」、填思域代理端口（默认 8789，不能与中转监听端口相同）并重启服务，路由器把这个端口转发到本机。家里的电脑在 MyCoAI 里选「思域」启动 Claude Code，只填中转根地址和自己的个人令牌，配置目录、代理和证书由 MyCoAI 准备。

控制面在中转端口的 `/v1/siyu` 下（列可用官方账户、建会话、续租、关闭），只认 `Authorization: Bearer` 个人令牌；思域没开时回 503。「思域」页列出进行中的会话，可以手动结束。思域发出的请求和中转机上原生 Claude Code 发出的一样；客户端配置不对时中转直接拒绝并读出是哪一项，不会发给官方。家里每台电脑都改用思域后，可在项目设置里勾「关闭旧接法的官方账户请求」。

## 设备维护

站点设备编号在新站建立时生成一次，日常重启、升级、登录和账户导入沿用已有编号。「设备维护」页允许管理员确认后手动更换；维护等待完整官方响应和本站 CLI 结束，失败可继续同一个操作，独立 API 继续可用。个人令牌、会话和用量归属保持。设备更换不能解除账户限制，也不会自动重新登录或试请求。临时脱敏取证默认关闭，最多十分钟或一百条样本。详见[站点设备维护、升级与恢复](../../docs/usability/SITE-IDENTITY.md)。

## 用量与金额

管理员在「用量」页面按使用者、上游、时间范围、接口类别、模型及结果筛选，可按天或小时汇总。个人打开中转根地址下的 `/my-usage`，输入自己的个人令牌查询；令牌不进入网址或浏览器存储。改名和轮换保留历史归属，旧令牌及停用令牌不能查询。

每条记录显示调用类型、实际走的上游、模型、输入/输出及缓存 Token、结果、发送状态和金额；每个数都带单位读出（例如「12,345 个 token」「成功 29 次」），币种读中文名。Token 采用上游实际报告；累计 SSE 用量只更新，不反复相加。缺少或中断的用量保留已知部分并标明不完整，全部未知显示「未知」。Count Tokens 是估算请求，Models 不计 Token；管理检测、健康检查和 HEAD 预热不计入个人消耗。

金额优先使用明确返回的上游费用；没有费用时，可在「用量 → 配置模型估算费率」按已保存上游和模型填写每百万 Token 的单价及币种。未配置时金额未知，估算始终标明来源，不等同于实际账单；不同币种和来源分开汇总。未知单价留空，明确免费才填 0。价格在发送时保存快照，改价不影响历史。支持的返回费用字段、单位和实际结果见[用量验证](../../docs/usability/USAGE-VALIDATION.md)。

记录按 UTC 请求开始时间保留 40 × 24 小时，严格早于截止点才删除；恰在边界保留。启动及每小时按 500 条一批清理，查询始终过滤窗口。显示和小时/天分组使用时区，但不会按本地午夜删除。配置、使用者、令牌和费率不随用量清理。

起始记录或发送标记保存失败时，服务拒绝发送请求。结束保存不受客户端取消影响，最多尝试三次；失败会在用量页面提示并写入 `usage_storage_failure` 元数据日志。启动恢复遗留请求为「中断 / 不完整」，不能据此推定零消耗。同一实例同时只允许一个服务运行，命令行管理仍可并发使用。

## 数据、升级与备份

业务数据保存在 `--home` 下的 `.state/relay.db`，使用 SQLite、WAL、外键和短事务，运行时经 EF Core 通用仓储读写。数据库保存管理员密码哈希、使用者、令牌哈希/版本、配置、已保存上游与在用记录、每次上游尝试、逐请求用量和费率；用量表不保存提示词、回答或凭据。上游凭据、证书私钥和管理 Cookie 密钥受当前 Windows 用户的 DPAPI 保护，`.state` 只允许该用户和 SYSTEM 访问。

当前库版本是 11。新程序打开旧版本的库时，先把旧库整份备份到 `.state/upgrade-backups/` 下按时间与版本命名的文件夹，再按顺序事务升级；升级中丢了数据会报出来，不会悄悄继续。回退程序时必须恢复升级前的完整配套备份，旧程序不能打开新版本的库。

更早的 JSON 版本（`.state/server.json`、`account.dpapi`、`tls.dpapi`、`relay-ca.pem`）升级前停止旧服务，再用新程序指定同一个 `--home`：

- 原始文件先复制到 `.state/legacy-backups/`，再用事务导入数据库；导入失败不修改原文件。
- 原有个人令牌、启停状态、设备 ID、User-Agent、凭据与证书保留；旧客户端名成为默认显示名。
- 旧实例还需在本机网页创建管理密码；这不会改变已迁移的个人令牌。
- 成功迁移只执行一次。此后 JSON 是旧数据备份，不再参与配置更新；不要继续编辑它管理新版本。
- 仅迁移管理员指定的本项目目录，不读取官方 Claude 登录文件。

备份时停止服务，复制完整 `.state` 和同目录的 `.relay-instance`，恢复时保持配套。**不要只复制正在运行中的 relay.db**，WAL 中可能还有已提交数据。数据库或实例标记遗失、损坏、权限异常时拒绝启动，不会自动开放重新设置；请恢复备份。DPAPI 数据换 Windows 身份后不能保证解密；换电脑用上游页的加密导出与导入，见[搬到另一台电脑](../../docs/usability/MOVE-TO-ANOTHER-PC.md)。

## 保留的命令行入口

网页和命令行调用同一数据库服务，可以并发管理；服务运行时，命令行的使用者管理动作经本机管道交给服务执行，令牌撤销立即生效。建议用列表中的主键指定使用者：

```powershell
.\HouseholdRelay.exe clients list --home D:\RelayData
.\HouseholdRelay.exe clients add --display-name 小王 --home D:\RelayData
.\HouseholdRelay.exe clients disable --id 使用者主键 --home D:\RelayData
.\HouseholdRelay.exe clients enable --id 使用者主键 --home D:\RelayData
.\HouseholdRelay.exe clients rotate --id 使用者主键 --home D:\RelayData
.\HouseholdRelay.exe clients rename --id 使用者主键 --display-name 新显示名 --home D:\RelayData
```

为兼容旧操作，可用 `--name office` 查找原客户端。CLI 创建/轮换仅在终端输出本次新令牌；请妥善保管终端记录，不重定向到共享日志。不会再写入含明文令牌的默认 `clients/` 目录。

`account` 继续支持本机终端隐藏输入上游凭据，并加密保存为一家新的上游，不会直接替换在用的上游；请在网页获取模型、测试后再切换。`init --host 域名` 保留旧版私有 CA 配置能力，证书保存到数据库，不探测 Claude Code 或自动创建使用者；已有证书时拒绝覆盖。

已经迁移的 HTTPS 入口继续使用原证书、监听端口和上游，可在网页下载原 CA 的公共信任包。TCP 映射应透传到本机 HTTPS 端口；映射、DNS 与证书信任分别配置。既有客户端包可继续运行 `client --bundle 文件夹`。

## 转发行为

- 只开放 POST `/v1/messages`、POST `/v1/messages/count_tokens`、GET `/v1/models`、HEAD `/api/hello`，以及思域控制面 `/v1/siyu` 和个人用量 `/my-usage`。
- 个人令牌可通过 `Authorization: Bearer ...` 或 `x-api-key` 传入；同时传入不同令牌时拒绝。思域控制面只认 Bearer。
- 默认全局并发 2、每人 1、最多排队 16、每人每分钟 120 次。限流和并发绑定不可变使用者 ID，改名或轮换不能重置它们。
- SSE 按完整事件即时刷新、取消释放资源；不自动重放，不跟随上游跳转。每家上游各自记 429 冷却和 401/403 暂停，测试通过后恢复；冷却和暂停是进程内状态，重启清空。
- 账户模式使用 Bearer，Anthropic 预设添加 OAuth beta；兼容中转按明确选项选择。API 默认 x-api-key，也可显式选择 Bearer，不携带 OAuth beta、不改账户设备元数据。
- API 模式保留客户端的有效 User-Agent；兼容账户模式使用项目设置里的统一 User-Agent；官方账户从本机原生 Claude Code 取得客户端身份，取不到时本地拒绝。发往官方账户的请求正文由客户端生成，中转不改正文；请求头里的 `anthropic-beta` 与 `Accept-Encoding` 按客户端这一次发来的原样带上，其他上游的 `Accept-Encoding` 固定为 `identity`。
- 根 URL、结尾 /v1 和自定义路径前缀均可配置；前缀保留，/v1 只添加一次。非认证 query 保留，下游 query 随后追加；相同参数允许重复，按原顺序传给上游，不猜测覆盖语义。配置地址禁止内嵌凭据及认证 query。
- 默认 HTTPS 并验证证书。回环/RFC1918/IPv6 唯一本地地址须显式允许，HTTP 只接受这些范围；DNS 解析后检查并按验证 IP 建连。上游代理在「项目设置」里全局一份（不使用、自动检测系统代理、手动指定），转发、获取模型、测试和 Claude Code 检测都用它；已启用代理却取不到地址时请求被拒绝，不会悄悄直连。
- 响应头只返回必要 request-id、retry-after、x-should-retry 和 Anthropic 限流头；不返回 Cookie 或未知敏感头。JSON 和 SSE 事件内替换当前上游凭据及其 URL/base64 表示，保留正常错误类型和消息的其余内容；非 JSON 错误换为安全错误说明。JSON 成功响应上限 16 MB，错误和单个 SSE 事件上限 1 MB，不缓存整条流。
- 没有在用的上游时，已认证模型请求返回明确的 503。`/healthz` 只表示进程可达（存活检查，回 `{"ok":true}`，另一台电脑装好信任后用它核对证书），不说明能不能用；带个人令牌的 `/status` 只提供运行状态，不是个人用量。
- 能不能用看就绪检查：本机管理端口上的 `http://127.0.0.1:8788/readyz`（只听回环，对外中转端口没有这个入口），逐项报「数据库能不能打开」「在用的上游配没配好」，都好回 200，有一项不好回 503 并读出是哪一项。
- 中转回给客户端的错误在 `error` 之后带 `request_id`（中转请求编号）；家人报错时报这串，管理员在事件日志里按它查。
- 日志在数据目录的 `logs` 文件夹：`events.log` 每个中转请求一行（请求编号、使用者名、路由、状态、上游名称、尝试次数、错误类型），`errors.log` 记兜底接住的意外异常与框架警告（只有异常类型、阶段、请求编号、上游主键）。两种各限 5 MB、留 3 份轮换，中文按原样写。不记录请求/响应正文、密码、上游凭据、个人令牌或代理地址。

## 证书

私有 CA 证书验证名称 SAN、有效期、服务器用途及本实例的确切信任根。CA 私钥与服务器私钥都用 DPAPI 保存；换地址或服务器证书快到期时，在「HTTPS 入口」按「用现有私有 CA 重签服务器证书」，CA 指纹不变，家人不用重装信任。旧版建的私有 CA 当初没留私钥，第一次换地址或续期只能新建一次 CA（每台客户端重新核验并安装），之后就只重签。证书到期前 30 天起，概览、HTTPS 入口与连接说明三页提示。任何一次覆盖证书（新建、重签、导入）之前都留上一份，HTTPS 入口可「退回上一份证书」（地址与端口一起退回）。证书或地址更新后重启生效。公共信任包只有 CA 公共证书、安装脚本与说明。

以后采用公网可信 CA 时，可导入 PFX：验证私钥、域名 SAN、有效期、服务器用途、系统证书链与吊销状态；密码不保存。正在用私有 CA 时，导入要先勾选确认项（服务端也核对）。证书无法验证时保留本机管理入口并拒绝启用 HTTPS。两种方式均保持正常 TLS 校验。本期由程序直接终止 TLS，不提供管理反向代理配置或受信代理头入口；保存地址不会自动配置域名、防火墙或公网映射。

## 开发与验证

```powershell
dotnet build HouseholdRelay.sln -c Release
dotnet run --project tests/Tests -c Release --no-build
dotnet publish src/HouseholdRelay -c Release --self-contained false -o artifacts/HouseholdRelay-release
```

源码分四个项目：`src/Core`（领域类型与纯规则，只引用通用仓储的抽象项目）、`src/Application`（服务、仓储与外部来源接口及用例服务，只引用 Core 和抽象包）、`src/Infrastructure`（SQLite 与 EF Core、DPAPI、证书、上游 HTTP、Claude Code 进程等实现）、`src/HouseholdRelay`（网页、命令行入口与组合根）。通用仓储在 `Helpers/Repositories`。所有服务经 `Microsoft.Extensions.DependencyInjection` 构造函数注入，各层分别提供 `AddApplication()`、`AddInfrastructure(...)` 登记方法，主程序在 `Composition/CompositionRoot.cs` 统一组装。命名规则写在根目录 `.editorconfig`，构建时执行：私有字段 `_camelCase`，`src` 里的异步方法以 `Async` 结尾。

Razor Pages、密码哈希、Cookie 和 CSRF 使用 ASP.NET Core 自带组件，不引入前端构建链；依赖包的版本以各项目文件为准。测试为自定义 .NET 测试程序，全部只连本机模拟上游，逐项打印 PASS/FAIL；要真实 Claude Code 命令行的几项默认不跑。浏览器旅程（`tests/Tests` 下的 `*-browser.cjs`）使用 Playwright 和无窗口 Edge，改网页后全部跑一遍；要真实上游的 `real-*.cjs` 只在验收需要时跑。

各阶段的验收记录（含失败记录和未执行项）留在仓库的 `docs/usability` 下，例如[私人部署验证](../../docs/usability/PRIVATE-DEPLOYMENT-VALIDATION.md)，不随发布包发出。
